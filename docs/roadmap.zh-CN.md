# 开发范围与下一步

InfiniLoader 的目标是：模型文件加载一次，让后续进程快速、可靠地复用。核心提供文件缓存、内容与代际检查、使用期租约、内存预算和安全回收；模型执行与请求调度交给消费者。

当前优先验收以下内容，不以增加功能数量为目标：

1. 用日常调试的一个真实模型和框架，通过已有 `start/run` 路径验证结果一致、重复加载耗时与内存占用。
2. 连续重复加载、退出、停止与复用，检查 FD、内存及残留进程是否持续增长，并验证源变化与失败恢复。
3. 保持安装、最小使用流程、支持环境与故障信息清楚可复现。公开性能结果应带模型 revision、引擎版本、命令、样本和测试范围。

后续优化应由这些测量发现的瓶颈驱动，例如重复文件扫描、校验或复制。先记录实际成本，再决定是否需要新的缓存策略或接口。

已有实现的成本需要单独量化并逐步收敛：磁盘构建目前按 cache root 串行；实验分片导出会按 rank 重复生成完整 catalog，TensorStore 初始化也有重复全量校验。优先考虑缩短构建锁范围、在一次导出任务中复用受校验的快照，并用稳定 FD 和 seals 减少重复读取。调整前后都必须保留源变化和错误发布的检测，不能直接删除校验来换取速度。

实验 MoE 的参考计算仍位于 `experts.py`；后续可将计算示例与驻留接口分离。真实引擎验收应分别记录文件读取、校验、映射、参数安装、格式转换、H2D 和初始化成本，避免把预热准备时间遗漏在比较之外。

显式分片、TensorStore 和 GPU 专家池保留为[实验接口](distributed.md)。它们不是核心 `start/run` 的依赖，也不作为前期缓存版本的生产引擎兼容保证。在线拓扑迁移、量化内核、路由调度和通用集群服务不属于当前交付范围。

此前的较大范围建议保存在[历史路线](archive/2026-10-26-roadmap.zh-CN.md)，用于说明原始评估，不代表当前承诺。
